# Algorithms, computing systems and machine design

This release covers the requested 58 topics with **56 new labs and two extended existing labs**. Bearing L10 life (`bearinglife`) and two-DOF modal analysis (`modal2dof`) retain their original routes and solvers and now have diagrams and subject tags. The generated [catalog](CATALOG.md) is the executable inventory; this release brings it to 297 unique labs in 21 sections.

**Networks & Operating Systems** and **Cryptography & Information Theory** are new sidebar sections, each with a live section preview. DSA additions remain in Data Structures & Algorithms. Mechanical additions use the Mechanical section’s subject filter: Vibration & rotor dynamics, Machine design, and Mechanisms & dynamics. Search composes with both section and subject selection.

## DSA: real states and certificates

All 18 additions use the existing algorithm workbench, with editable inputs, pseudocode, replay, keyboard scrubbing, state tables, predictions, worked examples and portable run exports. Intermediate snapshots are independent objects. Complexity notes distinguish core algorithms from the extra memory needed to retain replay frames.

Red–black black height follows the root-excluded, black-null-leaf-included convention. Skip-list searches follow explicit forward links, whose complete level chains are independently checked. Suffix doubling uses an explicit stable merge sort so comparison counts match across JavaScript engines. String comparison counters include terminating mismatches. Aho–Corasick caches fallback transitions and keeps terminal-output links rather than copying all inherited pattern lists into every state; replay tables expand those links only for inspection.

## Networks and operating systems

| Lab                          | Model actually implemented                                                                                                                    | Reference check                                                                                                 |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| TCP congestion control       | RTT-epoch Reno-style abstraction: doubling up to a threshold, additive growth, timeout versus duplicate-ACK loss response                     | Loss-free start 1,2,4,8,9,10; a timeout restarts at one segment                                                 |
| Go-Back-N / Selective Repeat | Discrete data/ACK events, one data send per tick, one tick propagation each way, fixed five-tick timeout, specified packet IDs lost only once | No-loss transmission count N; SR retransmits exactly the once-lost packets; every packet is delivered in order  |
| Slotted ALOHA / ideal CSMA   | Explicit slotted renewal model with idle-boundary attempts and L-slot success/collision occupancy; seeded channel simulation                  | L=1 gives the ALOHA formula; long-run seeded useful time approaches the renewal prediction                      |
| Distance-vector routing      | Synchronous cost-vector rounds, one failed destination link, optional poison reverse, infinity clipped to 16                                  | A disconnected line counts upward to infinity; poison reverse blocks its two-node stale-route loop              |
| CIDR                         | Unsigned IPv4 block arithmetic, prefix/host bits, mask and usable-address conventions                                                         | 192.168.10.77/26 maps to .64–.127; /0, /31 and /32 checked                                                      |
| Banker / deadlock detection  | Snapshot maximum-claim safety analysis, or outstanding-request detection with separate semantics                                              | Banker agrees with completion-order enumeration; a two-process circular resource hold is detected               |
| Disk scheduling              | FCFS, SCAN and C-SCAN over cylinders 0–199, with physical circular wrap counted                                                               | Classic head-53 case gives travel 640, 331 and 382 respectively when initially sweeping upward                  |
| Producer–consumer            | One atomic instruction per scheduled P/C character, counting semaphores, mutex, blocked queues and reserved-permit transfer                   | Random interleavings preserve capacity, nonnegative semaphore counts and produced−consumed=occupancy            |
| Virtual memory               | 16-bit VA, 4/4/8 directory/table/offset split, LRU TLB and frame replacement, demand faults and invalidation                                  | Evicted translations cannot remain hits; offset is preserved; latency components are checked explicitly         |
| CPU scheduling               | Nonpreemptive SJF/priority and preemptive three-level MLFQ with quanta 1/2/4 and periodic priority boosts                                     | Each job executes exactly its burst; finishes, waiting time, turnaround and idle time are independently counted |

These models expose their event assumptions. They are not a live TCP/IP stack, router emulator, operating-system kernel or calibrated hardware timing model. The CSMA lab deliberately names its idealized sensing model rather than claiming a general unslotted throughput formula. Banker safety is not automatically proof of current deadlock. Disk travel is not a measured seek-time prediction.

## Cryptography and information theory

| ID              | Behavior                                                                                                 | Reference and scope                                                                                                                                        |
| --------------- | -------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `sourcecoding`  | Entropy, actual Huffman prefix codes, mean length and redundancy                                         | Four equal symbols give H=L=2. Single-symbol practical code length one is explicitly distinguished from entropy zero.                                      |
| `rsa`           | Prime validation, extended Euclidean inverse, square-and-multiply encryption/decryption                  | p=61,q=53,e=17,m=65 → n=3233,d=2753,c=2790,m′=65; small noncoprime message residues also round-trip.                                                       |
| `diffiehellman` | Prime and primitive-root validation, separate public/shared modular computations                         | p=23,g=5,a=6,b=15 → A=8,B=19,shared=2. Agreement does not authenticate either party.                                                                       |
| `vigenere`      | Repeating-key encryption, inverse check, monogram counts and index of coincidence                        | ATTACKATDAWN / LEMON → LXFOPVEFRNHR. ASCII letter input, uppercase normalization; not an automatic key-recovery attack.                                    |
| `hashavalanche` | Full SHA-256 one-bit avalanche and a separate deliberately truncated birthday experiment                 | NIST “abc” digest and Node crypto comparisons across block/padding boundaries; collision probability and duplicate-output counts are different quantities. |
| `viterbicode`   | Actual rate-1/2 (7,5) convolutional encoder and four-state hard-decision Viterbi decoder with zero tails | Every eight-bit payload round-trips noiselessly; noisy path metric matches exhaustive terminated paths. More errors can defeat decoding.                   |

The RSA/DH numbers and classical cipher are educational and explicitly unsuitable for protecting data. There is no secure key generation, RSA padding, authenticated exchange or side-channel defense. The SHA implementation is portable educational code checked against standard vectors; it is not a separately certified cryptographic module. Truncated 8–20-bit birthday collisions do not claim a collision in full SHA-256.

Numerical results and plotted values are not capped to the schematic. Material-specific limits, fatigue, contact loss, nonlinear motion and manufacturing checks are excluded unless explicitly modeled.

## Verification and release workflow

`tests/deep-algorithms.test.js` and `tests/machine-systems.test.js` contain the references above, seeded property checks, parser/domain cases and HTTP parity. API handlers dispatch to the same pure solvers; numerical studies run in a cancellable browser worker. Replay frames contain data, not executable callbacks. New JSON inputs have bounded dimensions and numerical magnitudes; untrusted text is escaped or added through DOM text nodes.

`e2e/machine-systems.spec.js` covers every new and reused release workbench on desktop/mobile, API agreement, current navigation, keyboard replay, reset, invalid-input recovery, shared save/compare/export and representative axe scans. Existing browser suites also discover the new algorithm entries, and all section previews use solver data. Registry-derived counts replace old fixed catalog-count assertions.

The published npm 0.1.0 package remains its immutable earlier snapshot. A source package built from this release contains the expanded registry; publishing a new package version is a separate release action.
